# DigUp 中文与离线模型定制版设计

`brucetoo/DigUp` 在 `main` 中维护中文和内置模型功能，通过审阅
合并 PR 吸收 `ARahim3/DigUp main` 的优化。本文记录当前实现与
发布约束，不再是待审阅提案。操作命令见
[定制版维护](fork-maintenance.md)。

## 实现范围与约定

改造覆盖 macOS 原生应用和 Windows Tauri 应用。
源码实现不等于最终安装包已通过平台验收。

- 首次运行默认简体中文，设置中支持切换 English，保存用户选择
- 覆盖引导、搜索、设置、菜单、状态与错误提示；文件名、代码内容、
  日志及开发者 CLI 不翻译
- 语言切换刷新应用界面；系统原生对话框由操作系统语言决定
- macOS 和 Windows 安装包携带完整模型，首次运行不下载模型
- 继续使用上游固定版本的 EmbeddingGemma 2 Q8_0，不改搜索算法
- 保留此前编辑器选择回显修复，避免上游同步时重复引入
- 定制版发布只使用自己的 Releases 手动更新，两平台均关闭自动安装

默认约定：模型约 865 MB，可接受安装包增加相应体积；继续保持本地
索引与本地推理，不新增遥测或云端推理。Linux 不要求内置模型，
但共享界面和公共构建逻辑必须保持兼容。

## 实现结构

采用独立翻译资源、包内模型资源和 Git 合并同步。相比直接把英文
改成中文，这支持切换语言，并减少后续上游文案更新时的冲突。
相比定期重放整套补丁，保留上游提交历史的合并更容易审查来源、
冲突和已经被上游接纳的修复。

## 双语界面

语言设置使用明确的 `zh-Hans` 和 `en`，缺省为 `zh-Hans`。旧版
没有语言字段的设置同样默认中文；显式选择英文后不得被同步、
升级或重启覆盖。

macOS 的 `L10n.swift` 使用 JSON 本地化资源与可观察语言状态。
英文源码模板是键，`\(...)` 插值转换为 `{0}`、`{1}`。
`Localization/zh-Hans.json` 保存中文翻译。SwiftUI 界面、
AppKit 菜单与窗口标题都接入语言选择；动态数字和状态使用完整
模板，避免把用户文件名和动态值作为翻译键。权限说明和最终
`.app` 中的本地化资源仍属于打包验收范围，不能以源码资源存在
替代安装包核验。

Windows 的 `shell/ui/i18n.js` 提供统一 `t` 翻译函数，
`shell/ui/zh-Hans.json` 保存中文字典；英语使用原文。
语言持久化于设置
文件，通过 Tauri 事件通知所有已打开的窗口。静态 HTML、
JavaScript 动态提示与 Rust 产生的用户提示均纳入翻译边界。

中文遗漏回退英文以保证界面可用，同时 `scripts/check-fork.py`
读取实际源码和字典，报告可静态解析的未翻译键。
应用内新增语言选项；布局沿用现有设计，不改搜索语义和快捷键。

## 包内模型

模型资源以 `Sources/DigUpKit/ModelFiles.swift` 为版本与校验值的
权威来源。`scripts/bundle-models.py` 在构建阶段读取名称、
大小、revision 和 SHA-256；优先
使用指定本地目录或构建缓存，没有时下载到缓存。验证通过后才
复制到安装包。模型不提交到 Git，也不使用 Git LFS 保存权重。

macOS 将模型放入 `Contents/Resources/Models`；Windows 将模型
放入安装目录的独立 `models` 资源目录，通过 Tauri 的资源路径
解析传给 helper。模型不放进频繁重建的 helper 目录。

运行时区分显式开发/测试路径、验证通过的包内模型、
现有用户模型目录。定制安装包的包内模型缺失或损坏时给出修复
安装提示，不自动启动网络下载。开发者 CLI 保留下载能力，
用于构建与上游兼容。

包内模型直接读取，避免首次运行额外复制 865 MB。
构建时先取得权重和许可证，逐文件验证后生成 `bundled.json`
和 `MODEL-NOTICES.txt`。`--verify-only` 使用当前源码的固定值
检查实际安装目录，不信任 marker 自报的版本。
运行时校验、损坏提示和离线首次搜索必须分别在两平台验收。

构建验证覆盖大小、SHA-256、实际包路径及模型许可证。必须在
Windows 安装包完成后的目录中验证，不能仅检查构建暂存目录。

## 源码同步

fork 的 `main` 用于定制版，`upstream-main` 保存已合入的纯上游
基线。工作
分支承载每次改造，按功能拆分提交：语言基础、翻译资源、模型
打包与加载、同步自动化。上游原地址只用于取源码。

`scripts/sync-upstream.sh` 与 `.github/workflows/sync-upstream.yml`
支持手动触发及每周一 UTC 03:23 检查。
自动任务只获取上游、建立同步分支与 PR，不直接更新发布分支，
不自动发布安装包。

每次同步执行以下流程：

1. 在临时 clone 获取两方 `main`，验证基线为双方祖先并记录目标
2. 从 fork `main` 合并到完整 SHA 命名的 `sync/upstream-<SHA>`
3. 有冲突时 abort，保留两条主分支并创建或复用 fork 冲突 issue
4. 无冲突时读取候选源码与实际翻译资源，检查翻译和模型固定值
5. 创建草稿 PR，检查失败也在正文报告；同目标已有 PR 不重复创建，
   不覆盖原同步分支，并显式 dispatch 只读 `fork-checks.yml`
6. 人工平台验收与合入后，下次同步仅快进纯上游基线；发布另行手动执行

同步过程不使用 `reset --hard` 或 force push 覆盖 fork 的定制
历史。已有同步 PR 时复用；已关闭但上游目标仍未在 `main`
历史中的 PR 需要人工处理。冲突时只创建源码报告，不发送人员消息。

`--dry-run` 和 `--no-publish` 仍在临时 clone 合并与检查，
但不推送或调用 GitHub API，支持本地仓库远端。
`scripts/tests/test_fork_*.py` 在隔离仓库内验证成功、冲突、
重复执行、固定值变化、翻译缺失和工作目录保护，不访问网络。

模型 revision 或校验值变化时，旧缓存不能进入新包。更新模型
资源和许可证后再次构建，沿用上游关于向量版本和索引迁移的
决策。新增英文提示必须补中文，遗漏在同步检查中明确报告。
Swift 的直写与插值、JS 的模板、静态三元分支和字符串相加可检查；
变量、间接调用、HTML 和 Rust 动态消息仍需 UI 测试。
模型固定值与 `--base` 提交不同会失败，要求人工审阅而非自动接受。
Swift 测试、macOS 应用构建和 Windows 安装验收不在同步任务中执行。

此前 PR #84 的编辑器选择修复若已被上游合入，依靠 Git 历史
识别共同提交，不重复维护第二套实现。

## 定制版更新与发布

Windows 配置使用 `com.brucetoo.DigUp`，更新入口只打开
`https://github.com/brucetoo/DigUp/releases`，不咨询上游 updater。
macOS 同样默认使用 `com.brucetoo.DigUp`，`Updates.swift`
只打开自己的 Releases，上游 feed 和公钥已从 Info.plist 移除。

目前没有自己的签名或公证凭据，发布策略是两平台关闭自动 updater，
只手动获取自己 fork 的发布包，不复用上游公钥或 feed。
源码同步不依赖发布签名。macOS 构建显式复制双语资源和本地化权限
说明，并在最终 `.app` 中验证模型与代码签名。

发布默认先生成可审阅构建产物；签名、公证和正式发布需使用
维护者配置的凭据。macOS 可在本机验证，Windows 编译和安装
验证在 Windows runner 执行，不能将 macOS 检查宣称为 Windows
安装验证。

## 验收

验收覆盖功能行为与同步保护。同步机制由本地隔离测试验证；
以下应用行为是发布门槛，不表示已在 Windows 或正式安装包验证。

- 新设置与旧设置首次打开均显示中文，切换英文后重启保持英文
- 引导、搜索、设置和菜单保持同一语言，动态状态也可切换
- 完整安装包在断网、空用户模型目录下完成首次加载与搜索
- 包内模型损坏时有明确错误，不隐式联网、不卡在无限重试
- macOS `swift test` 和 App 构建通过，翻译资源进入实际 app
- Windows 测试、安装包构建、安装后模型路径及离线加载通过
- 同步上游无冲突变更可创建 PR，有冲突时保留定制历史并报告
- 模型版本变化及翻译缺失能够被同步检查发现
- 两平台均不会自动安装上游原版更新

## 决策记录

实现遵循：默认简体中文与英语切换、模型构建时下载而运行
时本地读取、模型保持上游固定版本、通过合并 PR 同步源码、
手动定制版更新与独立签名边界。同步不自动发布、不自动合入、
不覆盖定制历史；运行时禁用旧更新入口由父任务完成。
